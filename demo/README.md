# demo/демо.pns — relying-party пример

Минимальное клиентское приложение (OAuth2/OIDC relying-party),
показывающее полный Authorization Code + PKCE round-trip против живого
дозорного: логин → согласие → обмен `code` на токены → `/userinfo` →
страница с разобранными claims `id_token`.

## Запуск

1. В каталоге `дозорный/` (родительском): `panos старт.pns` — поднимет
   сам identity provider на `http://127.0.0.1:8080`, напечатает пароль
   администратора в лог.
2. Открыть `http://127.0.0.1:8080/admin`, войти этим паролем, вкладка
   "Клиенты" → Добавить:
   - имя — любое
   - redirect_uri — `http://127.0.0.1:9090/callback`
   - scope — `openid profile email`
   - публичный — нет
3. Скопировать `client_id`/`client_secret` из ответа в константы
   `CLIENT_ID`/`CLIENT_SECRET` вверху `демо.pns`.
4. `panos demo/демо.pns` — поднимет демо-приложение на
   `http://127.0.0.1:9090`.
5. Открыть `http://127.0.0.1:9090/`, нажать "Войти через дозорный".

`code_verifier` передаётся через `state` (не сессию/cookie) — намеренное
упрощение для демки без сервер-side состояния, см. комментарий в начале
`демо.pns`. Не паттерн для боевого relying-party.
